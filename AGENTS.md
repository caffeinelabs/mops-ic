# AGENTS.md

Motoko library (`mops` package `ic`) providing the IC management canister interface (`aaaaa-aa`): generated types plus a thin actor wrapper.

## Build, test

This is a Motoko/mops project. There is no separate build, lint, or format step.

```bash
mops install                      # install dependencies
mops test --replica dfx Call                 # dfx 0.30.1: create_canister, ECDSA, and Schnorr
mops test --replica pocket-ic HttpRequest    # PocketIC 16.1.0: HTTPS outcall pricing
# CI and publishing run both with mops 2.24.0.
```

CI (`.github/workflows/mops-test.yml`) runs both on push to `master` and on pull requests, as the `test` and `test-pocket-ic` jobs. `mops-publish.yml` runs both before `mops publish --no-test`, because `mops publish` runs every test file on one replica. The split exists because each replica lacks something the other has. The `dfx` 0.30.1 replica has chain-key signing keys and HTTP outcalls, but implements an earlier draft of `ic0.cost_http_request_v2` that rejects the specified parameters. PocketIC under `mops test` implements the spec, but has no signing keys and makes no outcalls.

## Layout

- `src/` — library source. `Call.mo` and `lib.mo` are hand-written; `Types.mo` is generated.
- `test/` — tests (`*.test.mo`), run by `mops test`. `Call.test.mo` needs the `dfx` replica; `HttpRequest.test.mo` needs PocketIC.
- `did/ic.did` — upstream Candid spec mirror; `src/Types.mo` is generated from it.
- `scripts/pascal_types.py` — converts generated `snake_case` type names to `PascalCase`.

## Conventions and gotchas

- **`src/Types.mo` is generated — never hand-edit it.** It carries a `// This is a generated Motoko binding.` header. Add helpers to `src/lib.mo` or a new sibling module instead. See `REGENERATING.md` for the full regeneration flow.
- Regeneration produces `PascalCase` type names (field and method names stay `snake_case`) via `scripts/pascal_types.py`. Regenerating requires `didc` ≥ 0.6.x.
- Tool versions are pinned in `mops.toml`: toolchain `moc = 2.1.0` and `pocket-ic = 16.1.0`, minimum requirement `moc = 2.1.0` (`Prim.costHttpRequestV2`).
- Every system API `src/Call.mo` calls is imported into each canister that imports the module, used or not, and the canister fails to install on replicas without it. `Prim.costHttpRequestV2` is already such a requirement; avoid adding more, such as `Prim.subnetSelfNodeCount`.
- `[moc].args` in `mops.toml` sets compiler flags (e.g. `-W=M0223,M0236,M0237`); keep them when running `moc` manually. `moc` 2.0 rejects `--default-persistent-actors` (actors are persistent by default).
- The public consumer pattern is `import { ic } "mo:ic";` and `import IC "mo:ic/Types";` — stable across regenerations, don't change casually.
- `.mops/` and `mops.lock` are gitignored (generated by `mops install`).
- Publishing is automatic: bumping `[package].version` in `mops.toml` on `master` triggers `mops-publish.yml`, which publishes and tags the release. Don't run `mops publish` by hand.
- When changing the public surface (`src/Types.mo`), bump `[package].version` in `mops.toml` and add a matching entry to `CHANGELOG.md`.
